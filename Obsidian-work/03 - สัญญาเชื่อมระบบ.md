# ข้อตกลงส่งภาพและผลตรวจระหว่างส่วนต่าง ๆ

> [!summary] ใช้หน้านี้ทำอะไร
> กำหนดให้ทุกส่วนใช้รูปแบบภาพและผลตรวจแบบเดียวกัน จะได้ต่อหน้าเว็บ โมเดล และวิดีโอเข้าด้วยกันได้

## ใครส่งอะไรให้ใคร

| คน | ส่งอะไร |
|---|---|
| 2 | ชุดภาพ, รายชื่อประเภท, ไฟล์ `data.yaml` และสถิติจำนวนภาพ |
| 3 | `best.pt` และฟังก์ชันตรวจภาพหนึ่งภาพ |
| 4 | ฟังก์ชันปรับภาพและผลเปรียบเทียบ |
| 5 | ฟังก์ชันอ่านคลิปทีละภาพและเขียนคลิปผลลัพธ์ |
| 1 | หน้าเว็บที่เรียกฟังก์ชันข้างต้นและแสดงผลให้ผู้ใช้ |

ก่อนเริ่มเชื่อม ให้ทีมกรอกชื่อประเภทจริงจาก Dataset และยืนยันข้อตกลงด้านล่าง

## รูปแบบภาพที่ใช้ร่วมกัน

ให้ฟังก์ชันส่งภาพเป็นภาพสีแบบ **RGB** เป็นหลัก ขนาดภาพคือความกว้าง × ความสูง × 3 ช่องสี

OpenCV บางคำสั่งอ่านภาพเป็น **BGR** ซึ่งสลับลำดับสีจาก RGB ถ้าสีออกน้ำเงิน/แดงผิด ให้ตรวจจุดแปลงสี อย่าส่งภาพคนละแบบโดยไม่บอกผู้รับ

## ผลที่ฟังก์ชันตรวจภาพควรคืน

คนที่ 3 ทำฟังก์ชันตรวจภาพหนึ่งภาพ ตัวอย่างรูปแบบผลลัพธ์:

```python
{
    "detections": [
        {
            "class_name": "helmet",
            "confidence": 0.91,
            "bbox_xyxy": [14, 28, 130, 165]
        }
    ],
    "counts": {"helmet": 1},
    "annotated_rgb": image_rgb
}
```

- `class_name` คือชื่อประเภทตาม Dataset ไม่จำเป็นต้องเป็น `helmet`
- `confidence` คือคะแนนความมั่นใจระหว่าง 0 ถึง 1
- `bbox_xyxy` คือตำแหน่งมุมซ้ายบนและขวาล่างของกรอบ
- `annotated_rgb` คือภาพที่วาดกรอบแล้ว

คนที่ 1 ใช้ผลนี้แสดงหน้าเว็บ คนที่ 5 ใช้ฟังก์ชันตรวจภาพเดียวกันกับเฟรมวิดีโอ

## ข้อควรระวังเรื่องการนับ

รูปเดียวมีหลายกรอบได้ จึงนับกรอบตามประเภทในรูปนั้นได้ สำหรับวิดีโอ คนเดิมอาจอยู่ในหลายเฟรม การบวกทุกกรอบจากทั้งคลิปไม่ใช่จำนวนคนที่ไม่ซ้ำ ถ้ายังไม่ได้ทำระบบติดตามคนให้แสดง “จำนวนกรอบที่ตรวจพบ” หรือจำนวนต่อเฟรมแทน
