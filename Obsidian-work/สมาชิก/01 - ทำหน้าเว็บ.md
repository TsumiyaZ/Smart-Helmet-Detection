# คู่มือคนที่ 1 — ทำหน้าเว็บและแสดงผล

> [!summary] หน้าที่ของคุณ
> ทำหน้าเว็บให้ผู้ใช้เลือกรูป กดตรวจ แล้วเห็นผลจากโมเดล คนที่ 3 ทำโมเดลให้เรียกใช้ คนที่ 4 ทำฟังก์ชันปรับภาพ และคนที่ 5 ทำส่วนอ่าน/เขียนวิดีโอ

## วิธีทำทีละส่วน

### 1. คุยเรื่องรูปแบบผลกับเพื่อนก่อน

ถามคนที่ 3 ว่าฟังก์ชันตรวจภาพชื่ออะไร รับภาพสีแบบไหน และคืนข้อมูลอะไร ตกลงให้ได้อย่างน้อย: ภาพที่วาดกรอบแล้ว, รายการสิ่งที่พบ, ชื่อประเภท และคะแนนความมั่นใจ ดู [[Obsidian-work/03 - สัญญาเชื่อมระบบ|ข้อตกลงส่งข้อมูล]]

### 2. ทำหน้าเว็บพื้นฐาน

ใน `app.py` ให้มีชื่อโครงงาน คำอธิบายสั้น ๆ ช่องเลือกรูป ปุ่มตรวจ และส่วนแสดงผล ใช้ Streamlit ซึ่งเป็นเครื่องมือทำหน้าเว็บด้วย Python

### 3. ต่อการตรวจภาพ

เมื่อผู้ใช้เลือกรูปและกดตรวจ ให้ส่งรูปไปยังฟังก์ชันของคนที่ 3 แล้วแสดงรูปที่มีกรอบ ตรวจว่าสีไม่เพี้ยนและกรอบอยู่ตำแหน่งถูกต้อง

ระหว่างรอโมเดล ใช้ผลตัวอย่างเพื่อจัดหน้าจอได้ แต่เขียนกำกับว่าเป็นตัวอย่างและเอาออกก่อนส่งงาน

### 4. แสดงผลที่คนทั่วไปอ่านเข้าใจ

- แสดงชื่อสิ่งที่ตรวจพบ
- แสดงคะแนนความมั่นใจเป็นเปอร์เซ็นต์ เช่น 0.86 แสดงเป็น 86%
- แสดงจำนวนที่พบแยกตามประเภท
- ถ้าไม่พบอะไร ให้บอกว่า “ไม่พบวัตถุที่โมเดลรู้จักในภาพนี้” อย่าสรุปว่าไม่มีหมวก เว้นแต่โมเดลและชุดภาพรองรับคำตอบนั้น

### 5. ต่อส่วนปรับภาพและวิดีโอ

เพิ่มตัวเลือกปรับภาพเมื่อคนที่ 4 ส่งฟังก์ชันมาแล้ว สำหรับวิดีโอ ทำช่อง upload และเรียก `process_video` ของคนที่ 5; คนที่ 5 เป็นคนอ่านคลิปทีละภาพ ส่วนคุณแสดงความคืบหน้าและคลิปผลลัพธ์

ตรวจว่าเปิดใช้/ปิดใช้การปรับภาพแล้วเห็นผลจากการประมวลผลจริง ไม่ใช่แค่เปลี่ยนข้อความบนหน้าเว็บ ให้คนที่ 4 ระบุชื่อวิธีและค่าที่ใช้ ส่วนวิดีโอให้จำกัดชนิดไฟล์ที่รองรับ แสดงว่ากำลังประมวลผล และทำให้ผู้ใช้เปิดดูหรือดาวน์โหลดคลิปที่ตรวจเสร็จได้

### 6. จัดการกรณีผิดพลาด

แสดงข้อความเมื่อผู้ใช้ไม่ได้เลือกรูป ไฟล์เปิดไม่ได้ หรือหา `best.pt` ไม่เจอ อย่าให้หน้าเว็บปิดตัวโดยไม่มีคำอธิบาย

### 7. ส่งงานให้ทีม

ส่ง `app.py`, รายการโปรแกรมที่ต้องติดตั้ง, วิธีเปิดแอป, ภาพหน้าจอ และแจ้งคนที่ 5 ว่าขั้นตอนใดใน README ต้องตรงกับแอป

### 8. ทดลองใช้เหมือนผู้ใช้จริง

ให้เพื่อนเปิดเว็บตาม README โดยไม่ช่วยบอกขั้นตอนระหว่างทาง แล้วลองภาพที่มีวัตถุ, ภาพที่ไม่พบวัตถุ, ภาพที่ระบบไม่รู้จัก และวิดีโอสั้น ตรวจว่าผู้ใช้รู้ว่าต้องกดตรงไหน รออะไร และดูผลตรงไหน ถ้าทำไม่สำเร็จให้จดข้อความที่เห็นและแก้หน้าเว็บหรือ README
