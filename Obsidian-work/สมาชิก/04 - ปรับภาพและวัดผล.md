# คู่มือคนที่ 4 — ปรับภาพและวัดผล

> [!summary] หน้าที่ของคุณ
> เลือกวิธีปรับภาพหนึ่งวิธีที่ช่วยกับภาพหมวก แล้ววัดว่าโมเดลตรวจถูก/พลาดอย่างไร ต้องมีตัวเลขและตัวอย่างภาพอธิบายผล

## ส่วน A — ทดลองปรับภาพ

### 1. ดูภาพจาก Dataset ก่อน

ขอภาพตัวอย่างจากคนที่ 2 แล้วดูว่าเจอปัญหาอะไร เช่น มืด ภาพหม่น หรือหมวกอยู่ไกล ถ้าภาพชัดอยู่แล้ว อย่าปรับภาพโดยไม่มีเหตุผล

### 2. เลือกวิธีปรับภาพ 1–2 วิธี

โจทย์ต้องการเทคนิคปรับภาพ 1–2 วิธี เลือกอย่างน้อยหนึ่งวิธีที่เหมาะกับภาพจริง เช่น CLAHE (ช่วยให้ส่วนมืดและสว่างแยกกันชัดขึ้น) ถ้าจะใช้สองวิธี ให้ลองแยกทีละวิธีก่อน แล้วค่อยดูผลเมื่อใช้ร่วมกัน เพื่อบอกได้ว่าแต่ละวิธีช่วยหรือไม่ ดู [[Obsidian-work/00 - คำศัพท์ง่าย ๆ|คำศัพท์ง่าย ๆ]] ได้ถ้าไม่คุ้นชื่อเทคนิค

เลือกจากปัญหาที่เห็นในชุดภาพ เช่น ถ้าภาพมืดหรือรายละเอียดหมวกจมหาย ค่อยทดลอง CLAHE; ถ้าภาพมีจุดรบกวน ค่อยทดลอง Median Filter อย่าเลือกหลายวิธีเพียงเพื่อให้มีชื่อเทคนิค และอย่ากำหนดล่วงหน้าว่าวิธีนั้น “ดีขึ้น” จนกว่าจะเทียบผลจริง

### 3. ทำไฟล์แยก

สร้าง `src/preprocessing.py` รับภาพและคืนภาพที่ปรับแล้ว เก็บภาพก่อน/หลังไว้เทียบ สีของภาพต้องไม่เพี้ยนและขนาดต้องไม่เปลี่ยนโดยไม่จำเป็น

### 4. เทียบกับภาพเดิม

ขอโมเดลและชุด validation จากคนที่ 3 แล้วตรวจภาพชุดเดียวกันสองรอบ:

1. โมเดลตรวจภาพต้นฉบับ
2. ปรับภาพด้วยวิธีที่เลือก แล้วให้โมเดลเดิมตรวจ
3. บันทึกค่ากับตัวอย่างผลทั้งสองแบบ

ใช้โมเดลและภาพ validation ชุดเดิมในการเทียบ หากปรับแล้วผลแย่ลง ให้รายงานตามจริงและไม่ต้องเปิดการปรับนั้นเป็นค่าเริ่มต้น นำวิธีที่เลือกไปเชื่อมกับหน้าเว็บโดยคุยกับคนที่ 1 และให้การตรวจวิดีโอใช้วิธีเดียวกันเมื่อทีมตกลงว่าจะปรับทุกเฟรม

จดเงื่อนไขการเทียบไว้ทุกครั้ง: ชื่อโมเดลเดียวกัน, รายชื่อภาพชุดเดียวกัน, ค่าความมั่นใจเดียวกัน และบันทึกว่าเปิด/ปิดวิธีปรับภาพ การเปรียบเทียบจึงตอบได้ว่าความต่างเกิดจากการปรับภาพ ไม่ใช่เปลี่ยนหลายอย่างพร้อมกัน

## ส่วน B — วัดผลโมเดล

### 1. ใช้ชุดภาพให้ถูก

ใช้ validation เพื่อเลือกแนวทางระหว่างทำ และใช้ test ตรวจผลสุดท้าย อย่าใช้ภาพฝึกมาสรุปว่าโมเดลทำงานดีกับภาพใหม่

### 2. เก็บตัวเลขพร้อมคำอธิบาย

บันทึก precision, recall และ mAP ที่ YOLO แสดง โดยจดด้วยว่าใช้ชุดภาพใดและใช้โมเดลไฟล์ไหน ดูความหมายง่าย ๆ ใน [[Obsidian-work/00 - คำศัพท์ง่าย ๆ|คำศัพท์ง่าย ๆ]]

- precision ต่ำ: โมเดลอาจตีกรอบผิดบ่อย
- recall ต่ำ: โมเดลอาจพลาดสิ่งที่มีอยู่จริง
- mAP ใช้สรุปคุณภาพการหาตำแหน่งกรอบและแยกประเภท

กรอกผลจริงลงตารางนี้และใส่ชื่อชุดภาพให้ครบ:

| การทดลอง | Precision | Recall | mAP | ชุดภาพ | หมายเหตุ |
|---|---:|---:|---:|---|---|
| ภาพเดิม | … | … | … | Validation | … |
| หลังปรับภาพด้วย … | … | … | … | Validation | … |
| ผลสุดท้าย | … | … | … | Test (ถ้ามีป้ายกำกับ) | … |

ถ้าเครื่องมือไม่ได้รายงานค่าบางตัว ให้เขียนว่าไม่มีค่า ไม่ต้องคำนวณหรือแต่งตัวเลขขึ้นเอง การเลือกวิธีจาก validation ทำได้ระหว่างทดลอง แต่ให้เก็บ test ไว้รายงานผลสุดท้าย ไม่ใช้ test ปรับเลือกวิธีซ้ำไปมา

### 3. ดูรูปที่โมเดลพลาด

เก็บตัวอย่างอย่างน้อยบางภาพที่โมเดลตรวจผิด แล้วเขียนสาเหตุที่เห็นได้ เช่น ภาพมืด หมวกเล็กมาก ป้ายกำกับไม่ชัด หรือโมเดลสับสนสองประเภท

### 4. สรุปให้คนที่ 5

ส่งตารางผลกับภาพตัวอย่างให้คนที่ 5 นำไปใส่ README และสไลด์ ตัวเลขในเอกสารต้องตรงกับผลที่ YOLO แสดงจริง
